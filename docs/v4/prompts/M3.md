# Milestone M3 — worker prompts, verbatim

Written by the manager before the milestone ran. The harness prepends one line to
each prompt: the task id and title, the branch, "do not commit", and the request for
real commands and real output as evidence. Nothing else is added.

M3 designs the passage annotation and draws the sample. M3.1 (the guideline, the
four-vote rule, the agents, the protocol) and M3.2 (the gold-train dev split and the
passage inventory) run side by side; they share no file. M3.3 (the sampler and the
batches) runs after both. The manager fixes the sampling caps at the close from the
inventory counts and may order one re-draw. Every prompt starts with the same common
block.

Manager's decisions that the prompts carry:

- The rater output schema does not change. A result object keeps the ten keys of
  guideline 2.0, and the passage identifier keeps the key name `window_id`, so
  `03_collect.py`, `validate_batch` and `align_quote` work unchanged.
- The coders' rows enter the consensus as a fourth vote with the same weight. A coder
  row whose test type is outside the six names does not vote. A coder-only result
  cannot survive on its own vote; it is a singleton dispute like any other.
- Every passage label stays bronze. No label in the repository is gold, because the
  coder vote is one voice of four and the owner says the coders are not always right.
- The gold-train dev papers (15 % by paper, seed 0, stratified by `has_results`) are
  frozen before the inventory is built and never enter the rater sample or any
  training set. They are the gate set of M6.
- The inventory holds no passage text, only its sha256 and coordinates, as
  `dataset/windows/key.json` does. The sample file holds the texts of the drawn
  passages, as `dataset/windows/train.json` does.
- Default caps for the first draw: 900 passages with a gold result, every hard
  negative up to 400, 200 passages of damaged papers, 300 clean negatives. That is at
  most 1800 passages, at most 180 batches of ten, at most 540 rater runs. The manager
  revises the caps at the close from the inventory summary.
