# Three ports — implementation plan

> **For agentic workers:** the manager dispatches one agent per task with the task text
> below, reviews the evidence (tests run, parity output, diff), and sends work back
> until it meets the acceptance line. Design: `docs/superpowers/specs/2026-09-20-ports-design.md`.

**Goal:** an R package, a web package with a demo page, and an installable Python
package, all fed by one kit from the mother repository and proven by one parity file.

**Rules for every task:** venv python, git, ls, cat only (never `rm`, `certutil`,
`del`; delete inside python). Read the spec JSON, never restate a rule. Every new
function has a parity or unit test that runs to completion. Report DONE with the exact
commands run and their last lines, or BLOCKED with the reason.

## Track A — mother repository (sequential; sonnet unless stated)

### A1 `weights.json` and a numpy reference forward pass
- `pipeline/08_export.py`: for each zoo config write `weights.json` beside `tagger.onnx`:
  `{"unit", "layers", "hidden", "embed_dim", "gate_order", "embedding": [[...]],
  "rnn": [{"layer": 0, "direction": "forward", "W_ih": ..., "W_hh": ..., "b_ih": ..., "b_hh": ...}, ...],
  "out": {"W": ..., "b": ...}, "crf": {"transitions", "start", "end"} | null}`.
- `src/statcheck_ml/rnn_numpy.py`: `forward(weights, ids) -> logits` for GRU and LSTM,
  batched, PyTorch gate order, padding handled with a mask.
- Test: for each zoo config, `rnn_numpy.forward` matches the torch model's logits on 20
  dev windows to max abs diff < 1e-3 (float32 drift of a GRU over a long window is
  about 2e-4) and every argmax tag agrees.
- Acceptance: the test passes for all three zoo configs; `08_export.py` reruns clean.

### A2 Parity cases for every stage
- `tests/make_parity_cases.py` writes `tests/parity_cases.json` with sections
  `normalise`, `repair`, `prefilter`, `extract`, `model`, `model_logits`, `group`,
  `pvalue`, `pipeline` as the design table defines, from 10 corpus excerpts (when
  `data/clean` exists) plus hand cases; the committed file is regenerated with the
  corpus present.
- `pvalue` section: at least 60 rows over t, F, r, z, chi2, q; edge cases: df 1, huge
  statistic, p = 0, p text with 1–4 decimals, `<` and `>` operators, one-tailed no.
- `tests/test_parity_self.py`: the Python reference reproduces every section of the
  committed file.
- Acceptance: the self test passes; the file is committed; the old `normalise`-only
  runners (`tests/parity.mjs`, `tests/parity.R`) still pass on the `normalise` section.

### A3 The kit
- `pipeline/08_port_kit.py` writes `kit/spec/*.json`, `kit/model/<config>/{tagger.onnx,
  decoder.json, charmap.json, weights.json}`, `kit/parity/cases.json`,
  `kit/manifest.json` (`version`, `mother_commit`, `generated_from` = report commit,
  `files` sha256, `model_default` = the recommended config).
- `--config` selects the models to ship (default: the zoo's top-1 only).
- Test: the manifest verifies after export; a modified file fails it.
- Acceptance: `python pipeline/08_port_kit.py ports/statcheck-ml-r/inst/kit --config gru-crf`
  and the same for `ports/statcheck-ml-web/kit` run clean.

### A4 Python package and CLI
- `pyproject.toml`: console script `statcheck-ml = statcheck_ml.cli:main`; extras
  `train` (torch), `pdf` (pymupdf), default deps numpy, scipy, onnxruntime.
- `src/statcheck_ml/cli.py`: `statcheck-ml check <pdf|txt> [--model models/zoo/gru-crf]
  [--json]`; text output one line per result; JSON output the `run_text` report.
- Test: the CLI on `examples/sample_paper_damaged.pdf` returns the same results as
  `Pipeline.run_pdf`.
- Acceptance: `pip install .` in a fresh venv and `statcheck-ml check` work without torch.

### A6 Python package proof on every platform (sonnet)
- `python -m build` produces sdist and wheel; `twine check dist/*` passes; the wheel
  holds `statcheck_ml/spec/*.json` and `statcheck_ml/zoo/gru-crf/*` and nothing else
  from `models/`.
- `.github/workflows/python.yml` in the mother repository: matrix ubuntu, macos,
  windows × Python 3.10, 3.11, 3.12, 3.13; each job `pip install "./statcheck-ml[pdf,test]"`,
  runs `pytest statcheck-ml/tests -q` (the tests that need R, node or the corpus skip
  themselves), builds the wheel, installs it in a second venv, and runs
  `statcheck-ml check statcheck-ml/examples/sample_paper_damaged.pdf --json` and asserts
  results are present. A second job installs from the repository address
  (`pip install "git+https://github.com/rasoulnorouzi/ml-statcheck.git@${{ github.sha }}#subdirectory=statcheck-ml"`).
- `requires-python = ">=3.10"`; dependencies as minimums; no pin that only one
  platform can satisfy.
- Acceptance: the workflow is green on all twelve jobs after the first push; the
  README shows the badge.

### A5 Layout and records (manager)
- `.gitignore` adds `ports/`; `CONTEXT.md` gets the port layout decision; `PLAN.md`
  gets a version 3 table; `CLAUDE.md` names the port repositories.

## Track B — R package `ports/statcheck-ml-r` (sequential)

### B1 Skeleton, kit, normalise, extract (sonnet)
- `usethis`-style layout: `DESCRIPTION` (GPL-3, imports jsonlite, pdftools),
  `NAMESPACE`, `R/`, `tests/testthat/`, `inst/kit/` from A3, `LICENSE`, `README.md`.
- `R/kit.R`: `sc_kit()` loads and verifies the manifest (sha256 via `digest` or
  `openssl`), errors on mismatch.
- Move `r/normalize.R` and `r/extract.R` into `R/`; testthat tests for the `normalise`
  and `extract` parity sections.
- Acceptance: `R CMD check --no-manual` passes with no errors or warnings; both
  sections pass.

### B2 Model and Viterbi (opus)
- `R/model.R`: `sc_tag(texts, kit)` — encode with `charmap.json`, batched two-layer
  bidirectional GRU/LSTM from `weights.json` (one matrix product per step and
  direction over all windows), output layer, Viterbi from `decoder.json`; returns a
  list of tag vectors.
- Tests: `model_logits` section to 1e-3 with every argmax tag equal; `model` section exact tags; a timing test
  that 100 windows of 300 characters tag in under 10 seconds.
- Acceptance: both parity sections pass; timing recorded in the PR text.

### B3 Prefilter, repair, grouping, p-value, pipeline (sonnet)
- `R/prefilter.R`, `R/repair.R`, `R/group.R`, `R/pvalue.R` (pt, pf, pchisq, pnorm;
  the rounding rule of `pvalue.py` exactly), `R/pipeline.R`: `sc_check_text(text, kit)`
  returning the data frame of the design.
- Tests: parity sections `prefilter`, `repair`, `group`, `pvalue`, `pipeline`.
- Acceptance: all sections pass; `R CMD check` clean.

### B4 PDF input, docs, CI (sonnet; docs haiku)
- `sc_check(pdf, kit)` via `pdftools::pdf_text`; `README.md` with install and a
  three-line example; `NEWS.md`; `.github/workflows/check.yml` (R CMD check on
  windows, macos, ubuntu).
- Acceptance: `sc_check("sample_paper_damaged.pdf")` returns the Python pipeline's
  results (same statistics and verdicts); CI green on the first push.

## Track C — web package `ports/statcheck-ml-web` (sequential)

### C1 Skeleton, kit, normalise, extract (sonnet)

- Acceptance: `npm test` green.

### C2 p-value core (opus)
- `src/pvalue.js`: regularised incomplete beta and gamma (continued fractions), t, F,
  chi2 (and q), r-to-t, normal via erfc; `check()` with the rounding rule of
  `pvalue.py`.
- Tests: the `pvalue` section to 1e-9 relative on computed p and exact verdicts; the
  edge rows in particular.
- Acceptance: section passes; no dependency added.

### C3 Model, grouping, prefilter, repair, pipeline (sonnet)
- `src/model.js` (onnxruntime-web, WASM, batch of one window; Viterbi),
  `src/prefilter.js`, `src/repair.js`, `src/group.js`, `src/pipeline.js`:
  `checkText(text, kit)`.
- Tests: sections `model`, `group`, `prefilter`, `repair`, `pipeline` under Node.
- Acceptance: all sections pass.

### C4 PDF.js, demo page, Pages, docs (sonnet; docs haiku)

- `.github/workflows/test.yml` (Node 20, 24) and `pages.yml` (deploy `demo/` + `kit/`).

### D4 Tutorials (sonnet writes from executed examples; manager reviews)
Every code block in a tutorial is executed before it is written down, and the output
shown is pasted from that run. ASD-STE100 style. Each tutorial has the same spine so a
reader can move between languages:
1. What the tool does and does not do (finds results with a model; the verdict is
   arithmetic; bronze labels; no gold set).
2. Install, in every supported way, with what each way needs (Python: pip from the
   repository address, from PyPI when published, from a wheel; the `pdf` extra. R:
   `remotes::install_github`, `R CMD INSTALL`, CRAN when published; `pdftools`
   system requirement per OS. Web: the page, the npm package, the CDN script).
3. First run: one PDF, the printed table, what each column means (`source`, test type,
   statistic, degrees of freedom, operator, reported p, computed p, verdict, line).
4. Each stage, with the intermediate output shown for one damaged sentence: extract,
   normalise, repair, prefilter, find (regex, then model), check. Where each rule
   lives (`spec/*.json`) and what the kit manifest guarantees.
5. The API in full: every function, argument, default and return field, with one
   example each (Python `Pipeline`, `run_pdf`, `run_text`, `summarise`, the CLI flags;
   R `sc_check`, `sc_check_text`, `sc_tag`, `sc_kit`, `sc_kit_info`; web `checkPdf`,
   `checkText`, `loadKit`).
6. Reading a verdict: `consistent`, `inconsistent`, `decision_error`, `undecidable`,
   with one real example each, and the rounding rule.
7. Choosing a model, and switching to another zoo model.
8. Batch use: a folder of PDFs to one CSV (a full script in each language).
9. Limits and troubleshooting: what the prefilter drops, PDF engines, damaged text the
   model misses, common install errors on each OS.
Files: `statcheck-ml/docs/TUTORIAL_PYTHON.md` (mother repo, linked from README);
`vignettes/statcheckml.Rmd` in the R package (built by `R CMD check`, so every chunk
runs in CI) plus `docs/TUTORIAL.md` rendered from it; `docs/TUTORIAL.md` in the web
repo, linked from the demo page.
- Acceptance: every code block runs as written on a clean install; the manager
  reruns three blocks per tutorial at random and compares the output.
