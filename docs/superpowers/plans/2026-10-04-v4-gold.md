# Version 4 plan — the gold set, passages, a rebuilt noise layer, and a retrain

Date: 2026-10-04. Branch: `v4-gold`. Brief: `docs/superpowers/specs/2026-10-04-v4-gold-brief.md`.
Status: development and testing only. Nothing is pushed and nothing is published.

The manager (fable) plans, assigns, verifies and records. It writes no project code.
Workers run under the agents in `.claude/agents/`, each with the model of its
frontmatter unless the task is mechanical enough to go down. At most six workers run at
once. Every worker prompt is saved verbatim in `docs/v4/prompts/<milestone>.md` before
the milestone runs. Every accepted task gets one entry in `docs/v4/LEDGER.md`.

## Decisions fixed in this plan

### The gold split

| Bronze set | Papers | Goes to | Reason |
|---|---|---|---|
| holdout | 49 | gold test | the owner's decision |
| train | 181 | gold train | the shipped model trained on windows from these papers, so they are not an unseen test for it, and version 4 is compared against that model |
| none | 179 | two to one toward gold test, stratified by has-results and journal, seed 0 | the bronze-train papers already hold 1908 of the 2483 results, so the training side loses little and the test gains power and no-result papers |

Expected size: a gold test of about 168 papers (about 49 with results, about 500
in-scope results, about 119 no-result papers) and a gold train of about 241 papers
(about 2030 results). `pipeline/14_gold_split.py` writes `dataset/gold/split.json`,
which is committed and frozen. `src/statcheck_ml/gold.py` holds the guard that every
sampler and every training stage calls.

### The gold test is evaluated through one script and logged

`14_gold_eval.py` is the only reader of the gold test. It appends one line per run to
`results/gold_eval_log.jsonl`, so every evaluation against the gold test is on record
with the date, the commit and the model. No tuning decision reads the gold test: the
no-training fixes are measured on it before and after because they are bug fixes, not
tuned parameters, and the report says so.

### The benchmark is the original statcheck

The R package runs on the gold papers in four forms: the normalised full text, the
repaired full text, the repaired passages, and the PDF through `checkPDF`. The first
three run on the same text as every other system, so they measure extraction. The
fourth is what a statcheck user gets today.

### The old shipped model stays where it is

The version 2 runs stay in `models/<run>/`; `models/gru-crf-s0/tagger.onnx` is the old
shipped model and a baseline of the version 4 evaluation. Version 4 trains into
`models/v4/<run>/` and exports into `models/zoo/`, which replaces the shipped zoo once
the pre-registered rule has chosen.

### The processing unit becomes the merged passage

A spec change in `spec/prefilter.json` (version 2): overlapping windows merge into one
passage, read once. The Python port, the R port and the web port read the new spec;
none restates the rule. The brief measured this without training: the same recall,
15.8 M characters read instead of 28.1 M, 287 finds in no-result papers instead of 304.

### Annotation moves to the passage, with the coders as a fourth vote

The guideline goes to version 3.0 for passages. Three blind raters read batches of ten
passages. The coders' rows that fall inside a passage are a fourth vote with the same
weight; a result stays with two votes of four; a singleton or a three-way field conflict
goes to the blind adjudicator. The coders' scope differs from the guideline (they skip a
correlation without degrees of freedom and code CI, Wald and `b` rows), so a coder row
whose test type is outside the six names does not vote.

### The noise layer is gated on gold-train evidence, never on the gold test

Each family is a flag. A gate run trains `gru-crf` seed 0 for a short schedule with the
family on and off and measures on the gold-train dev papers (15 % of gold-train papers,
by paper, seed 0, held out of every gate run and of the final runs). A family stays when
it raises recall on its own real damage type and does not raise finds in no-result
papers.

### The shipped model is chosen by a rule written before training

The manager writes `docs/v4/preregistration.md` at the close of the noise milestone,
before any final training run starts. The rule names the dev sets, the metric, the tie
break, and the seeds. The evaluation milestone applies it and reports every candidate.

No model is raised because a task is hard. A hard task is split.

## Time and compute

Version 2 runs took 850 to 1800 seconds for 30 epochs on 1962 windows of 284
characters. The passage dataset holds longer units, so M7.1 measures seconds per epoch
on one run first. Ten runs at three in parallel on eight cores must finish within about
12 hours of wall time; otherwise the manager halts and hands the owner GPU commands.

## What halts the program

- A gold test paper found in any training or sampling input.
- A noise family that cannot be gated without the gold test.
- The training estimate above 12 hours on CPU.
- A port whose tests cannot pass against the new parity cases without restating a rule.
